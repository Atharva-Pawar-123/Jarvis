class StreamingTextToSpeech:

  __init__(self):
    - Load PiperVoice from config.PIPER_MODEL_PATH and PIPER_CONFIG_PATH
    - Initialize a threading.Queue() for audio chunk playback (self.audio_queue)
    - Initialize a threading.Event() for stop signal (self.stop_event)
    - Start a daemon thread running _audio_player_loop() continuously
    - Initialize self.sentence_buffer = ""  for accumulating streaming text
    - Initialize self.is_speaking = False
    - Log "Streaming TTS engine initialized."

  _audio_player_loop(self):
    PRIVATE DAEMON THREAD. Runs forever. Pulls audio numpy arrays from
    self.audio_queue and plays them sequentially with sounddevice.
    When self.stop_event is set: clear the queue immediately and stop playback.
    This thread never stops — it is always ready to play the next audio chunk.

  on_token(self, token: str):
    THE STREAMING INTEGRATION POINT. Called by LLMEngine._generate_streaming()
    on every token received from Ollama. Implements sentence boundary detection:

    Append token to self.sentence_buffer.
    Check if sentence_buffer ends with ".", "!", "?", or "..." followed by space.
    If a sentence boundary is detected:
      1. Extract the complete sentence from sentence_buffer.
      2. Clean it: strip markdown, remove special chars, fix abbreviations.
      3. Call _synthesize_and_queue(cleaned_sentence) in a background thread.
      4. Clear that sentence from the buffer.
    Return immediately — never block the token stream.

  _synthesize_and_queue(self, text: str):
    PRIVATE. Synthesize the text with Piper to a numpy audio array.
    Use io.BytesIO as a buffer — never write to disk.
    Put the numpy array into self.audio_queue.
    The _audio_player_loop thread will pick it up and play it.

  speak(self, text: str, blocking: bool = True):
    For non-streaming use (system messages, confirmations, errors).
    Clean the text first (strip_for_voice method).
    Synthesize the full text and play via sounddevice.
    If blocking=True: wait for playback to complete with sd.wait().

  stop(self):
    Set self.stop_event. Clear self.audio_queue. Stop current playback.
    Reset self.stop_event after clearing.

  strip_for_voice(self, text: str) -> str:
    Remove all markdown: **, *, #, `, _, ~, |
    Replace "e.g." with "for example"
    Replace "i.e." with "that is"
    Replace URLs with "the link"
    Strip leading/trailing whitespace.
    Return cleaned text.

  flush(self):
    If self.sentence_buffer has remaining text: synthesize and queue it.
    Wait for audio_queue to empty before returning. This ensures JARVIS
    finishes speaking every word even at the end of a response.

HOW STREAMING CONNECTS TO LLM:
--------------------------------------------------------------------------------

      Tokenize query and run BM25.get_scores()
      Get top n_results * 2 results by BM25 score
      Normalize BM25 scores to 0-1 range

    Step 3 — RECIPROCAL RANK FUSION (RRF):
      For each document: final_score = 1/(rank_semantic + 60) + 1/(rank_bm25 + 60)
      Sort by final_score descending
      Return top n_results documents

    Return list of dicts: [{text, score, source, metadata}]

  get_relevant_context(self, query: str) -> str:
    Call search(query, n_results=3)
    If no results above threshold 0.3: return ""
    Format results as a context string:
    "RELEVANT MEMORY:\n" + "\n".join([f"- {r['text']}" for r in results])
    This string is injected into the LLM messages before each response.

  extract_and_store_facts(self, user_text: str, assistant_response: str):
    BACKGROUND THREAD. After every conversation turn, call this.
    Send both texts to FAST_MODEL:
    "Extract any learnable facts, preferences, or important information from
     this exchange. Return a JSON array of fact strings. Max 3 facts.
     Return [] if nothing worth storing. Return ONLY the JSON array."
    Parse the JSON array. For each fact string: call add_fact().
    Run in daemon thread so it never blocks the voice loop.

  clear_all(self):
    Clear all ChromaDB collections and BM25 corpus.
    Log "Memory cleared, sir."

File to create: D:\JARVIS\modules\react_agent.py

This is the heart of what makes JARVIS genuinely AI-level. Replaces the
simple if/elif intent dispatcher with a true Reason+Act loop.

class ReActAgent:

PURPOSE: For complex requests, JARVIS will reason about what tools to use,
use them, observe results, reason again if needed, and synthesize a final
answer. Exactly how Claude, GPT-4, and Gemini work internally.

ATTRIBUTES:
  self.llm          → LLMEngine instance
  self.tools        → dict of {tool_name: callable} for all JARVIS capabilities
  self.max_steps    → 8 (maximum tool calls before forced conclusion)
  self.memory       → HybridRAGMemory instance

__init__(self, llm, tools, memory):
  Store all three. Register tool descriptions for the LLM.

get_tool_descriptions(self) -> str:
  Format all available tools as a description string for the LLM:
  "AVAILABLE TOOLS:\n" + "\n".join([
    f"- {name}: {description}" for name, description in tool_registry.items()
  ])

run(self, user_query: str, conversation_history: list) -> str:
  THE CORE REACT LOOP:

  Step 0: Check if this is simple (complexity_score < 5).
          If simple: skip ReAct, use direct generate() — faster.

  Step 1 — REASON:
    Build a ReAct system prompt:
    "You are JARVIS executing a request. You have access to tools.
     For each step, decide: do you need a tool, or can you answer directly?

     FORMAT each step as:
     Thought: [your reasoning about what to do next]
     Action: [tool_name] or [FINAL_ANSWER]
     Action Input: [JSON parameters for the tool] or [your final response]

     Available tools: {get_tool_descriptions()}

     Stop when you have enough information to give a final answer.
     Use FINAL_ANSWER as the Action when done."

    Add the user query. Call llm.generate() with this prompt.

  Step 2 — PARSE:
    Parse the LLM output for "Thought:", "Action:", "Action Input:" patterns.
    If Action is "FINAL_ANSWER": return Action Input as the response.
    If Action is a tool name:
      Look up the tool in self.tools.
      Parse Action Input as JSON for tool parameters.
      Execute the tool: result = self.tools[action_name](**params)

  Step 3 — OBSERVE:
    Add the tool result as an "Observation:" to the conversation.
    Loop back to Step 1 with the updated context (max self.max_steps times).

  Step 4 — FORCE CONCLUSION (if max steps reached):
    Send one final generate() with: "Based on everything above, give your
    final answer to the user now."
    Return that response.

  The entire ReAct loop runs in the main thread for voice interaction.
  For tasks >30 seconds: hand off to UltraPlan background agents.

  def hitl_gate(action_name: str, fn: callable, *args) -> str:
    tts.speak(f"Sir, I'm about to {action_name.replace('_',' ')}. Please confirm.")

    return "Action cancelled, sir."
